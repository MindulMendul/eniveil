# 이슈 #170 검증 기록

2026-11-09, Bun 1.4.4, 별도 SQLite 테스트 DB와 서로 다른 Chromium 계정 세션을 사용했다. 운영 데이터는 사용하지 않았다.

## 서버 검증

`apps/server/src/modules/lobby/social.test.ts`에서 다음을 검증한다.

- 앞자리 0을 포함한 PIN 확인 및 공개 응답의 PIN 해시 비노출
- 서로 다른 계정의 PIN 오입력도 방별로 합산하여 10회 실패 후 10분 잠금, 시간 경과 후 해제
- 친구방의 친구 관계 검사와 비친구에 대한 목록·입장 제한
- 방장 권한, 온라인 상태, 공용 로비 대기 상태 검사
- 중복 초대와 거절 응답의 중복 알림 방지
- 마지막 자리의 동시 수락 시 정원 준수
- 방장 변경과 로비 이탈에 따른 초대 무효화
- 초대 수락 시 비밀방 PIN 재검사
- 완료한 공동 게임만 판 수에 한 번씩 집계

## 실제 브라우저 검증

Playwright와 `/usr/bin/chromium`으로 1280×900의 독립된 계정 세션 3개와 390×844 모바일 화면을 사용했다.

1. 방 만들기에서 비밀방을 선택하고 `0001` PIN으로 2인용 작품의 방을 생성했다.
2. 대기방 친구 목록에서 프로필을 열어 닉네임과 함께한 게임 0판, 초대 버튼을 확인했다.
3. 초대 전송 후 프로필이 닫히고 수신자 오른쪽 아래에 초대 알림이 표시됐다.
4. 아니오를 선택해 방장에게 거절자의 닉네임이 포함된 알림이 표시되는 것을 확인했다.
5. 같은 친구에게 다시 초대하고 예를 선택했다. 잘못된 PIN은 차단됐고 수신자는 로비에 남아 있었다.
6. 올바른 `0001` PIN으로 수락해 방에 입장했고 서버의 참가 인원이 2명이 됐다.
7. 정원이 찬 상태에서 다른 온라인 친구의 초대 버튼이 비활성화된 것을 확인했다.
8. 모바일 화면에서 입장한 대기방을 확인했다. 위 흐름에서 브라우저 pageerror는 발생하지 않았다.

기본 `bash scripts/codex/verify.sh` 검증을 실행했다. `--browser`는 기존 저장소의 `test:e2e` 명령 부재로 종료 코드 1을 반환하므로 자동 브라우저 검증 통과로 표시하지 않는다. 위 실제 브라우저 조작 기록으로 UI 검증 근거를 남긴다.

## 동작 범위

친구 관계는 기존 계정 친구 기능을 사용한다. 초대는 2분 후 만료되며 서버 재시작 시에도 사라진다. 친구 관계와 완료한 게임 기록은 기존 SQLite 저장소에 유지된다. 초대는 자리를 예약하지 않으며 비밀방 PIN을 우회하지 않는다. 친구방의 기준은 현재 방장과의 친구 관계다.
