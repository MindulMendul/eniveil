# 이슈 #172 검증

2026-11-09, Bun 1.4.4와 별도 테스트용 SQLite DB를 사용했다. 운영 데이터는 사용하지 않았다.

## 서버

`play-analytics.test.ts`는 중복/늦은 이벤트, 활동·미측정 시간 분리, 탭별 순서, 본인 소유권, 익명 HttpOnly 소유 쿠키, 결말 전 평가 차단, MMR 비노출, 다인 채팅 권한, 독립적인 결말/평점, 방 삭제 후 기록 보존, 중도 이탈, 보관 기간 정리, 평점/게임 시작의 저장 실패 롤백, 중복 시작 재사용, 종료 유예 후 1인 방 정리를 검증한다.

기존 실제 HTTP·WebSocket 테스트도 새 종료 동작에 맞게 수정했다. 종료 후 return 명령을 거부하고, 첫 참가자가 평가하고 나가도 다른 참가자의 결말을 유지하며, 마지막 참가자 종료 후 방이 삭제되는 것을 확인한다. 이전 방의 지연된 종료 요청이 새 방을 닫지 않는지도 확인한다.

## 실제 Chromium

Playwright와 `/usr/bin/chromium`의 서로 다른 두 계정 세션(1280×900), 모바일 390×844에서 확인했다.

1. 방 선택 UI에서 덕일상사 방을 만들고 게임·스토리를 시작했다.
2. 시작 연출을 건너뛰고 실제 플레이 API로 단서를 수집·고발해 성공 결말을 만들었다.
3. 새로고침 후에도 본인 결말을 복구했다. 결말 중에는 평점과 다시하기 버튼이 없었다.
4. 첫 결말 대사에서 계속을 누르고 다시 새로고침했을 때 다음 대사부터 복구되는 것을 확인했다.
5. 마지막 대사까지 계속을 누른 뒤에만 별도 평점 화면이 표시됐다. 평가 화면에서 새로고침해도 유지됐다.
6. 5점 제출 후 로비로 돌아왔으며 해당 방이 삭제됐다.
7. 2인용 방에서 공개 채팅을 보내 상대 세션에 도착하는 것을 확인하고, 단서 공개→투표→결말을 진행했다.
8. 한 참가자는 결말 완료 후 4점 제출로 먼저 로비로 나갔다. 다른 참가자의 결말 화면은 유지됐다.
9. 다른 참가자는 모바일 화면에서 결말을 확인하고 평가를 건너뛰어 로비로 나갔다. 마지막 방도 삭제됐다.
10. 위 흐름에서 브라우저 pageerror는 발생하지 않았다.

`bash scripts/codex/verify.sh`를 실행한다. `--browser`도 실행했으며, 기존 저장소에 `test:e2e` 명령이 없어 해당 추가 단계는 종료 코드 1을 반환한다. 이를 자동 브라우저 검사 통과로 표시하지 않으며 위 실제 브라우저 기록을 별도 검증 근거로 사용한다.

## 해석 범위

수집·분석 스키마, 실력 지표의 초기 모델, 시각의 신뢰도, 미측정/누락 처리 및 90일/365일 보관 기준은 `docs/analytics/play-data.md`에 명시했다. 외부 음성·대면 대화는 수집하지 않으며 현재 지원하는 게임 내 채널은 공개 방 채팅이다. 내부 실력 값은 충분히 보정된 경쟁 순위가 아닌 성과 기반 초기 추정치다.

검증 후 다른 Bun 프로세스에서 같은 SQLite를 다시 열어 두 스토리의 세션·단계·행동·시간 분포가 조회되는 것을 확인했다. 방은 0개로 정리됐고, 채팅 1건과 평점 2건이 유지됐다.

## 리뷰 후 추가 검증

- 1인 수사의 알리바이 단계에서 용의자를 선택하고 질문한 뒤 새로고침했다. 같은 단계·선택한 용의자·진술이 복구됐다.
- 다인 단서 공개 단계에서 다른 참가자 페이지를 새로고침했다. 같은 세션과 discussion 단계가 유지됐다.
- 이전 완료 세션 ID를 브라우저에 남긴 상태에서 새 방을 시작했다. 이전 평점으로 튕기지 않고 새 스토리를 시작했다.
- 새 플레이에서 틀린 용의자를 고발했다. 실패 결말 중에는 평점이 없고, 계속을 누른 뒤에만 평가가 나왔다. 건너뛰기로 방이 삭제됐다. 실패 화면을 별도로 캡처했다.
- 수사 중 나가기를 눌렀을 때 즉시 abandoned로 저장되고 방이 삭제됐다.
- 별도 플레이의 수사 탭을 실제로 닫고 약 60초의 WebSocket 재접속 유예를 기다렸다. 방 삭제와 연결된 플레이의 abandoned 결과를 본인 API로 확인했다.
- 위 전체 흐름의 브라우저 pageerror는 0건이었다.

서버 회귀 테스트는 지연된 opening 로그의 결말 커서 오인 방지, 다른 탭의 단계 주장으로 서버 rating 방문을 변경하지 못하는 점, 90일 원문 삭제 후 행동 집계 보존, 다인 정답/완료 구분, 마지막 활동 기준 이탈 시간을 추가 검증한다. UI 캐시 테스트는 잘못된 단계·미발견 증거·유효하지 않은 용의자를 복구하지 않는 것을 검증한다.

## 결말 프로토콜·이전 버전 호환 검증

결말 API는 completed/skipped 명시값을 요구한다. scripted completed는 resolution의 마지막 커서가 있어야 하며, 빈 요청·opening 로그만으로 평점을 열 수 없는 회귀 테스트를 추가했다. 수정 후 실제 Chromium에서 성공 결말 전체 확인→평점, 실패 결말 확인→평점, 새로고침 복구, 다인 개별 종료를 다시 통과했고 pageerror는 없었다.

이전 버전 데이터는 원래 bearer였던 run ID의 1회 POST 복구, 다른 사용자 재소유 차단, 소유한 실행 재개 조회, 알려진 다인 참가자/역할 복구, 24시간 유예 후 미소유 실행 정리를 테스트했다. 원본 스토리가 없는 과거 완료 실행은 현재 스토리를 과거 결말로 사용하지 않으며, 부분 복구 실행은 정상 시간/실력 표본에서 제외하는 것도 확인했다. 이는 서버 회귀 테스트 근거이며 실제 운영 DB 업그레이드 검증으로 표시하지 않는다.

## 정리 작업·로그 마감 회귀 검증

- 정리 중 방 저장 실패를 주입했다. 해당 플레이/메모리 방 상태는 롤백되고, 나머지 오래된 플레이는 처리되며 다음 회차에 실패했던 플레이도 정리됐다.
- 별도 워크숍 스토리의 평가가 진행 중인 덕일상사 1인 방을 닫지 않는 것을 확인했다. 방 연결은 같은 스토리에만 허용한다.
- 완료·결말 확인·평점 제출 사이 마지막 heartbeat 이후의 UI 활동 시간과 긴 미측정 구간을 확인했다.
- 브라우저 저장소와 네트워크 실패를 모의해 120건을 큐에 쌓았다. pagehide는 종료 이벤트를 포함한 121건 모두를 50건 이하의 세 배치로 전달 시도하며, 중복 pagehide에서 종료를 재생성하지 않았다. beacon은 브라우저/네트워크 정책에 따른 최선의 전송이며 영구 오프라인의 전달을 보장하지 않는다.
