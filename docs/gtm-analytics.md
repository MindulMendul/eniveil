# GTM 분석 연결

`PUBLIC_GTM_CONTAINER_ID=GTM-56Q5K95G`를 빌드 시 설정한다. 운영 배포는 환경/저장소 변수 `GTM_CONTAINER_ID`를 사용하고 미설정이면 위 운영 컨테이너를 사용한다. QA는 전용 변수 `QA_GTM_CONTAINER_ID`만 사용하며 미설정이면 태그와 동의 UI를 비활성화한다. QA는 운영 변수나 운영 컨테이너로 자동 대체하지 않는다. 로컬에서 미설정 또는 잘못된 ID면 분석 UI와 태그를 비활성화한다. `PUBLIC_GA_MEASUREMENT_ID` 직접 로딩은 제거했다.

사용자 결정(#173): 첫 방문 모달에서 수집 범위를 선택하며 로그인·플레이에는 전체 동의가 필요하다. 기본은 GA만 허용하고 전체는 게임 품질 측정·난이도 분류·개인 실력 지표용 추가 기록까지 허용한다. 광고·마케팅 목적 사용은 두 범위 모두 금지한다. 앱은 광고 이벤트를 전송하지 않고 Google 광고 저장·사용자 데이터·개인화를 denied로 고정한다. 품질 측정용 Faro도 전체 동의 후에만 활성화한다.

동의는 서버의 HttpOnly 쿠키와 버전2 기록으로 검증한다. 브라우저 localStorage는 탭 간 변경 알림에만 사용하고 기존 v1 허용은 새 전체 동의로 취급하지 않는다. 현재 브라우저·계정에30일간 적용하고 첫 로그인 계정과 연결하며, 이후 계정 변경과 다른 기기에는 자동 이전하지 않는다. 기본으로 축소하거나 철회하면 해당 동의의 추가 기록을 즉시 삭제하고 진행 중 게임 연결·서비스 접근을 중단한다. 운영상 게임 상태·사용자가 제출한 평점과 이미 GA에 전송된 기록은 별도 보관 정책을 따른다.

## GTM 관리자 설정

관리자 권한이 있는 운영자가 다음 설정을 확인하고 게시해야 한다. 이 코드 변경으로 GTM 콘솔을 수정하거나 게시하지 않았다.

1. GA4 Google 태그의 자동 `page_view`를 끈다(`send_page_view=false`). 향상된 측정의 브라우저 기록 변경 기반 페이지 조회도 끈다. 별도 All Pages/History Change 페이지뷰 트리거를 만들지 않는다.
2. Google 태그/GA4 이벤트의 `page_location`, `page_title`, `page_referrer`, `language`는 앱이 보내는 dataLayer 변수로 명시적으로 설정한다. 쿼리·해시가 있는 기본 브라우저 URL이나 document.title을 다시 사용하지 않는다. Google 태그 초기 설정에서도 이 값을 사용하도록 첫 page_view 이벤트에서 초기화하거나 태그 순서를 보장한다.
3. 커스텀 이벤트 `page_view`를 GA4 page_view로 한 번만 전달한다. `page_dwell`, `story_start`, `story_abandon`, `story_attempt_end`, 기존 `case_*` 품질 이벤트는 각 이벤트 이름으로 매핑한다. `ad_impression`·`ad_click` 등 광고 이벤트는 전송하지 않는다. 필요한 속성은 analytics.js의 허용 목록을 사용하고 단서·용의자·장소 식별자나 DOM/입력값을 별도로 수집하지 않는다.
4. 클릭·폼·URL/DOM 자동 수집과 광고 태그는 해당 목적 및 제공자에 관한 안내·설정을 확인하기 전 추가하지 않는다. 앱의 동의 게이트는 컨테이너 로드를 차단하며, GTM 관리자도 동의 정책을 지켜야 한다.

## 검증

로컬·dev·QA·운영 각 환경에서 컨테이너 ID와 공개 origin을 확인한다. 새 브라우저에서 동의 전 GTM/gtag 요청0, 거부 후 새로고침 요청0, 허용 후 gtm.js 요청1, ko/en SPA 이동당 page_view1, gtag.js 직접 요청0을 확인한다. 초대 코드 쿼리/해시와 작품 제목·비공개 본문·정답·개인 정보가 앱 이벤트에 포함되지 않는지 검사한다. 관리자 Preview/GA4 DebugView에서는 자동 페이지뷰와 수동 페이지뷰가 중복되지 않는지 별도로 확인한다. 콘솔 권한·게시·실제 GA4 수신을 검증하지 못했다면 완료로 보고하지 않는다.
