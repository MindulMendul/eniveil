# 플레이 난이도 데이터 v1

스토리 ID·버전·플레이 ID·참가자 ID로 1인/다인 데이터를 연결한다. 게임 정답·투표·결과와 UI에서 관측한 행동을 구분한다. 수집 안내는 한국어/영어 개인정보 처리방침에 포함한다. 외부 GA 방문 분석과 별개인 게임 기능 데이터다.

## 저장소

- `play_sessions`: 스토리/버전, 모드, 원래 방 ID, 서버 시작/종료 시각, completed/failed/abandoned 결과, 본인에게 허용된 공개 결말. 방을 지워도 남는다.
- `play_members`: 참가자/역할, 보관 중인 최근 365일 범위의 같은 스토리 이전 플레이 횟수(0이어도 생애 첫 플레이로 단정하지 않음), 시작 시 실력 추정치와 산정 버전, 결말 완료/평가 완료 시각, 평점. 평점 NULL + 완료 시각 존재는 건너뛰기다.
- `play_events`: 스키마 버전 1. 이벤트 UUID, 서버 전역 순서, 플레이/사용자, 유형·단계·대상 ID, 서버 수신 시각(ms), server/client 출처, 클라이언트 식별자·순서·발생 시각. 클라이언트 시각·행동은 관측값이며 정답/권한 판단에 쓰지 않는다. 동일 플레이·사용자·UUID는 한 번만 저장한다. 늦은 이벤트도 원본은 보존하지만 최신 단계·시간을 되돌리지 않는다.
- `play_visits`: 단계별 각 방문의 진입/이탈·활동·미측정 시간. 재방문은 새 행이다. intro/cast/explore/alibi/cross/accuse/briefing/discussion/voting과 win/fail/reveal, rating을 분리한다. 이 표는 서버 전이만 반영한다. 세부 UI 단계는 play_ui_visits에서 별도로 분석한다.
- `play_ui_visits`: 탭별 UI 관측 방문. 클라이언트 주장 단계는 이 표와 원본 이벤트에만 남고 서버 확정 단계·결말·평가 상태를 덮어쓰지 않는다. 관리 조회에서도 observedStages/observedVisits로 별도 구분한다.
- `play_action_totals`: 원문 보관 만료와 별개로 유지하는 세션/사용자/단계/행동별 빈도. 재전송은 한 번만 합산하고 365일 보관한다.
- `play_devices`: 탭별 마지막 처리 순서. 새로고침/여러 탭에서 순서가 충돌하지 않게 한다.
- `play_skill`: 공개하지 않는 계정별 실력 추정 요약.

## 이벤트

서버: started, stage_entered, scene_advanced, evidence_found, evidence_revisited, accusation, vote, result, ending_completed, rating_submitted, rating_skipped, chat.
클라이언트: stage, location, inspect, question, evidence_present, suspect, evidence_select, hint, cue_next, cue_skip, visibility, heartbeat, exit, error.

클릭 위치 좌표나 DOM 전체를 수집하지 않는다. 조사 사물·증거·용의자 등 의미 있는 대상 ID를 남긴다. 채팅은 현재 방 참가자만 보낼 수 있는 공개 room 채널만 지원한다. 외부 디스코드·대면 대화는 수집할 수 없다. 비밀 채널을 추가할 때는 채널 권한과 수신 대상 검사를 별도로 구현해야 하며 현재 공개 채팅 API에 섞지 않는다. 원문을 포함한 이벤트는 공개 통계 응답으로 반환하지 않는다.

10초 heartbeat와 visibility/pagehide를 사용한다. 서버 수신 간격이 30초 이하면 직전 visible 상태의 경과 시간을 활동 시간에 포함한다. 간격이 30초를 넘으면 그 간격은 미측정 시간으로 남긴다. 비활성 시간은 활동 시간에 포함하지 않는다. 이 방식은 표본 기반 추정이며 장시간 연결 단절의 실제 활동 시간을 0으로 단정하지 않는다. 클라이언트 발생 시각은 원본 분석에 함께 제공하되 신뢰된 서버 시각을 덮어쓰지 않는다.

전송 실패 시 같은 UUID를 재전송한다. 브라우저 sessionStorage에 최대 500개를 보관하며 초과하면 최신 기록과 offline_queue_overflow 오류 이벤트를 보존해 누락 가능성을 표시한다. 강제 종료로 마지막 beacon까지 유실되면 30분 무활동 후 서버가 abandoned 처리한다. 서버 재시작 후에도 SQLite에서 이 상태를 복구한다. 중도 이탈의 유효 종료 시각은 정리 작업 시각이 아니라 마지막 활동 시각으로 남긴다.

## 내부 실력 지표

`performance-v1`은 경쟁 순위용 MMR이 아니라 난이도 분석을 위한 초기 성과 지표다. 서버가 판정한 1인 완료/실패가 3판 미만이면 NULL(미산정), 3판 이상이면 `800 + 400 × 성공 판 수 / 완료·실패 판 수`다. 중도 이탈과 정답을 판정할 수 없는 다인 데모는 업데이트하지 않는다. 매 플레이 시작 시 값을 고정해 이후 실력 변화가 과거 분석 구간을 바꾸지 않게 한다. 계정/닉네임/방/게임/공개 통계 API에 노출하지 않는다. 향후 실제 난이도 모델을 도입하면 새 산정 버전을 사용해야 한다. 이 지표를 정교하게 보정된 상대 실력으로 해석해서는 안 된다.

## 관리 조회

`STORY_ADMIN_TOKEN`의 Bearer 인증이 필요하다. 토큰 미설정/불일치는 거부한다.

- `GET /api/play/admin/stories/:storyId?version=N`: 스토리 버전별 완료·실패·이탈 세션과 판정 가능한 정답 여부, 단계별 평균/최소/최대·활동·미측정 시간, 실력대별 완료율·시간·평점, 단계·이벤트별 빈도. completionRate는 끝까지 진행한 비율이고 successRate는 판정 가능한 정답 비율이다. 다인 표결의 단독 최다 득표가 서버 정답 역할과 일치하면 참, 다르면 거짓이며 동률·정답 미설정은 NULL로 구분해 정답률 분모에서 제외한다. p50/p90 시간 분포는 최근 닫힌 방문 최대 10,000개 서버 확정 방문 표본과 표본 수를 명시한다. 세션 목록은 최근 500개다.
- `GET /api/play/admin/sessions/:id?after=SEQUENCE`: 참가자/시작 실력, 방문 기록, 원문 이벤트 500개를 서버 순서 기준으로 조회한다. 마지막 sequence를 다음 after로 보내면 이어서 읽는다. 채팅 원문과 최종 선택·결과도 이 권한에서만 원본으로 조회한다.

참가자는 `/api/play/sessions/:id`에서 자기 종료·평점 상태만 확인한다. 다인 결과는 종료 후에만 노출된다. 세션 ID를 안다고 다른 사람의 기록을 읽거나 평가할 수 없다. 로그인하지 않은 창작마당 플레이는 HttpOnly 소유 쿠키로 구분한다.

## 종료와 보관

결말 전체 완료/명시적 건너뛰기 뒤 평가를 표시한다. 평점 또는 건너뛰기는 참가자별로 한 번 확정하고 각자 로비로 나간다. 마지막 참가자 종료 시 방을 지운다. 먼저 끝낸 사람은 다른 사람의 결말·평가를 끊을 수 없다. 끝난 다인 방은 10분 유예 후에도 정리하며, 본인 결말/평점 복구는 방 존재와 무관하다. 종료 방은 참가·초대·재시작할 수 없다.

원문 이벤트·채팅은 90일, 종료 세션/참가자/방문·평점·행동 집계 및 실력 요약은 365일 보관 후 제거한다. 서버 시작과 1분 주기 정리에서 적용한다. 브라우저 대기 큐는 전송 성공 시 비운다. 계정 정보 삭제 요청 시 운영자는 관련 사용자 ID의 원문 이벤트, 방문, 장치, 참가자 및 실력 요약과 결말의 닉네임 등 개인 식별 내용을 함께 삭제/비식별화해야 한다. 관리자 원본 내보내기에는 일반 게임 참가 권한을 사용하지 않는다.

생애 누적 플레이 횟수는 보관 만료 이후 정확히 알 수 없다. prior_plays_scope=retained_365_days와 historyWindowDays=365로 범위를 명시하고, firstEverPlay는 미확정(NULL)으로 기록한다. 원문 90일 만료 뒤에도 행동 집계는 세션 요약과 같은 365일 동안 유지하므로 오래된 플레이의 힌트·행동 빈도를 0으로 오인하지 않는다. 이전 story_run_events와 story_ratings도 각 원문/평점 발생 시각을 기준으로 독립적으로 정리한다.

## 첫 배포의 기존 플레이 전환

이전 1인 API에는 소유자 필드가 없고 추측하기 어려운 실행 ID 자체가 접근 권한이었다. 배포 후 24시간의 고정 전환 기간에만 해당 기존 접근 권한을 POST 요청으로 한 번 교환해 인증된 사용자 또는 HttpOnly 익명 소유 쿠키에 묶는다. GET은 소유권을 만들지 않으며, 이미 연결된 플레이는 다른 계정으로 재할당하지 않는다. 전환 기간의 시작은 DB에 보관하므로 재시작으로 연장되지 않는다. 기존 클라이언트의 진행 요청도 이 교환을 거쳐 이어서 처리한다.

기존 다인 진행방은 저장된 참가자와 역할로 복구한다. 확보하지 못했던 과거 단계 시간과 신원은 추정하지 않고 timing_status=partial로 표시한다. 부분 기록은 정상 단계 시간 집계와 실력 보정에서 제외한다. 이전 완료 플레이의 불변 원본이 없으면 과거 결과만 보여주며 현재 수정된 스토리의 결말을 과거 결말로 대신하지 않는다. 원래 접근 ID가 유실된 익명 과거 플레이의 소유자는 알아낼 수 없으므로 임의의 계정에 붙이지 않는다. 미소유 과거 실행은 24시간 전환 유예 동안 보존하고, 기한이 지나면 과거 마지막 활동 시각을 기준으로 종료해 원본 보관 공간을 해제한다. 새로 소유권이 연결된 플레이에는 일반 30분 무활동 정리가 적용된다.

평가 단계 전환은 completed/skipped의 명시적 요청으로 남긴다. 대사형 결말의 completed는 resolution 장면의 최종 진행 위치 또는 재생 완료 기록이 있어야 한다. 명시적 skipped는 별도 건너뛰기 이벤트로 남기며, 대사 큐가 없는 결말은 completed 요청 자체를 결과 확인 동작으로 기록한다. 빈 요청으로는 평가 단계를 열 수 없다.
