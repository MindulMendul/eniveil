# 창작 기능 재구현 계획

## 현재 상태와 이번 변경

현재 코드는 .mstory 검증/가져오기, 기본 장면·대사 필드 편집, 초안 CRUD와 공개 작품 플레이의 기반이다. 사용자가 처음부터 작품을 설계하고 완성할 수 있는 창작 도구는 아니다.

`WORKSHOP_AUTHORING_ENABLED=false`를 공통 기준으로 작성/수정 버튼과 계정의 수정 진입을 숨겼다. 기존 편집 URL과 저장된 인증 복귀 경로는 작품 목록으로 이동한다. 별도 이미지 변환 입력/다운로드 UI는 제거했다. 기존 작품 탐색·플레이·개인 작품 데이터와 소유자 API는 유지한다.

## 구현 순서

1. **작성 모델과 완성 조건**: 먼저 현재 엔진이 지원하는 장면, 대사, 현장, 용의자, 단서, 고발 조건을 편집 모델에 대응시킨다. 분기 그래프는 현재 .mstory 스키마/런타임의 표현 범위를 확정하고 테스트한 후 편집 UI를 붙인다. 미지원 동작을 저장 가능한 것처럼 노출하지 않는다. 안정적인 ID와 참조 규칙, 필수 항목, 시작/종료 및 도달 가능성 검증을 정의한다.
2. **작품을 직접 만드는 편집기**: 작품 템플릿 → 장면 목록/연결 → 선택 장면의 내용·조건·단서 편집 순서로 만든다. 추가·삭제·재정렬·복제·되돌리기와 오류 위치 이동을 제공한다. 파일을 직접 수정하거나 .mstory를 가져오지 않아도 작품 하나를 완성할 수 있어야 한다.
3. **비공개 미리보기**: 소유자의 저장된 초안 또는 현재 작업본으로 플레이를 시작하고 특정 장면에서 재시작할 수 있게 한다. 공개 목록/일반 플레이 지표와 분리하며 공개 전에는 다른 사용자에게 초안·정답·역할 비밀을 보내지 않는다.
4. **관리 이미지 자산**: 각 이미지 입력은 독립 변환창 대신 공통 변환 모듈을 호출한다. WebP 인코딩 → 서버의 실제 바이트/크기 검증 → 소유자·치수·저장 키가 있는 자산 등록 → 편집기에서 자산 선택 순서다. 외부 URL 입력은 제공하지 않는다. 비공개/공개 자산 접근, 중복·용량 예산과 사용 중인 자산 삭제 규칙을 확정한다.
5. **저장·버전·공개**: 작업본 저장, 동시 편집 충돌 감지, 이전 버전 복원, 공개 전 검증을 연결한다. 공개 버전과 플레이 중 원본을 고정한다. 가져오기/내보내기는 보조 수단이며 제작의 필수 절차로 삼지 않는다.

## 다시 노출하는 조건

새 사용자가 UI만으로 유효한 작품을 만들고, 비공개 미리보기에서 끝까지 실행하고, 저장/재열기 후 공개 작품을 다른 계정에서 플레이할 수 있어야 한다. 깨진 참조·미지원 분기·정답 노출·소유권·키보드 접근·한/영·모바일 회귀를 검증한 뒤 별도 PR에서 작성 기능을 켠다.

## 공통 이미지 모듈

- `apps/web/src/shared/images`: UI 없는 `convertToWebp(Blob)`, 파일명/실제 헤더/치수 검증. PNG/JPEG/GIF/WebP 입력, 원본 최대10MiB, 가로·세로 각각4,096px 이하 및1,600만 픽셀 이하, 변환 WebP 최대1MiB. 초과 시 자동 축소 없이 거절한다. 브라우저 인코더 결과가 실제 image/webp인지 확인한다. GIF/움직이는 입력은 기존과 같이 첫 프레임 정지 이미지로 처리한다.
- `build.ts`: 신뢰된 빌드 원본을 Sharp로 실제 WebP 인코딩한다. 원본은 public 밖에 보관하고, public에는 생성된 WebP만 둔다. 개발/빌드 모두 같은 통합을 사용한다.
- `packages/shared/src/images.ts`: 바이트·픽셀·품질 정책과 관리 경로 등록부. 현재는 등록된 정적 자산만 허용하며 향후 서버가 검증·등록한 업로드 자산을 연결할 때 확장한다. 아무 `.webp` 주소나 신뢰하지 않는다.
- `ManagedImage.svelte`: 등록 경로만 출력하고 미등록/이전 외부 경로는 관리되는 기본 이미지로 대체한다. 작성 API도 외부·미등록 경로를 거절한다. 이전 URL은 DB에서 일괄 삭제하지 않고 응답에서 비노출한다.
