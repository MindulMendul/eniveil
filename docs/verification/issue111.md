# Issue 111

- 사용자 확인에 따라 친구 요청·수락 방식을 적용했다. 계정 로그인 사용자만 닉네임으로 계정을 검색하고 요청할 수 있다. 수신자가 수락하기 전에는 친구 목록에 포함하지 않는다.
- 변경 가능한 닉네임이 아닌 계정 UUID의 정규화된 쌍을 SQLite에 저장한다. 검색 응답은 ID·닉네임만 제공하며 인증 식별자·토큰·이메일은 공개하지 않는다. 기존 중복 닉네임 후보는 계정 키로 구별한다.
- 자기 자신·게스트·중복/역방향 요청을 거부한다. 수락·거절은 실제 수신자만 가능하고 요청 수·검색 빈도를 제한한다. 계정 탈퇴 시 연결을 같은 트랜잭션에서 정리하며 구글 로그아웃 시 관계는 보존한다.
- 2026-11-08 기본 verify 82 tests/4,965 assertions 통과. --browser는 기존 test:e2e 부재로 기본 검사 후 exit 1. 권한·수락·변경된 닉네임·재접속·거절·저장소 재개방·탈퇴 정리를 서버 테스트로 확인했다.
- 자체 메모리 DB 서버와 실제 Chromium: 한국어·영어 × 1440/320px에서 개발용 Google demo 계정 두 개로 검색→요청→수신자 수락→새로고침 후 친구 목록 유지, 가로 넘침 없음을 확인했다. 실제 Google OAuth 공급자 인증은 검증하지 않았다.
- UI 진입점은 마이페이지의 친구 영역이다. 로비의 플로팅 버튼/오프캔버스와 온라인 구분은 #112에서 추가한다. 운영 배포 없음.
